# 异常处理与兜底

| 情况 | 判断信号 | 处理 |
|------|----------|------|
| 需求定稿后用户改需求 | 新消息与任务书冲突 | 小改 → 更新任务书（复述确认）继续；大改 → 重走卡点①澄清，再回对应环节 |
| 派遣报 `not found` | Agent 调用返回可用列表不含该角色 | 角色文件未生效（本会话新建）或名字拼错。核对拼写；确认未生效则本会话**虚拟派遣兜底**（general-purpose + 契约段），报告注明降级 |
| 模板角色在库里缺位 | 团队模板引用的角色文件不存在 | 虚拟兜底或换库内相近角色，**向用户说明替换**后继续 |
| 模板环节与任务不匹配 | 合并时发现模板某环节在任务中不存在（如模板有开发而任务纯调研） | 合并时去掉该环节并在卡点②说明理由；差异过大 → 换模板或改走「库内现选」 |
| 模板与 skill 规则冲突 | 同一环节两边规定不同 | 用户拍板点以 skill 为准（卡点不可省）；执行细节以模板为准（领域经验）；都有道理 → 差异列进卡点②让用户选 |
| 执行中要改融合工作流 | 跳过/新增/重排阶段的需求 | 列出理由经用户批准后才改（走卡点②变更），改动记录进花名册 |
| 选角不匹配 | 角色带专属引擎/工具（mcpServers、WorkBuddy 引擎），行为与岗位要求不符 | 换库内其他角色或虚拟兜底；不硬凑 |
| 子 agent 失败/超时 | 返回错误或长时间无果 | 队长接管该子任务亲自完成，黑板与交付报告注明「队长代工」 |
| 开发卡死 | 同一问题 2 次尝试失败 | 升级攻关岗（带「已试过什么、卡在哪」的任务书）；库里无攻坚角色则虚拟兜底（契约：先证明，后攻坚） |
| 攻关失败 | spike 证明不可行 | 带证据请示用户：换路线 / 降需求 / 记技术债 |
| 质量审核发现问题 | design-review / qa-report 列出问题 | 审核岗直接做最小修复并复验（记录三要素：改了什么/为什么/怎么验证）；架构级/需求级/大范围问题报队长路由 |
| 审核不通过超限 | 返工 2 轮仍有阻断问题 | 三出口：降范围 / 记技术债 / 请示用户；审核岗手写门禁放行并注明遗留 |
| 用户在卡点③对设计提问题 | 用户确认时提出修改意见 | 队长修订设计 → 重走审核 → 再次请用户确认；用户驱动的循环不设轮次上限，每轮记录进 design.md「用户确认记录」 |
| 开发中发现设计缺陷 | 实现时发现设计走不通 | 回退卡点③：修订设计 + 重审 + 用户确认后再继续；已完成的合规代码尽量保留 |
| 会话中断后恢复 | 新会话用户说「继续」 | 读黑板（task-brief/manifest/dag.json/报告/门禁）→ 简报断点 → 从 dag.json 首个未完成节点继续。**不重新组队、不重问已定稿的需求** |
| dag.mjs 跑不起来 | node 缺失或脚本报错 | 降级：把任务依赖写成 markdown 缩进列表/表格放进 `.agent-team/dag.md` 让用户看文本版；不影响主流程 |
| 角色输出文件缺失 | 下一环节读不到输入 | 先向该角色 SendMessage 补写；实例已终结则重派；仍失败队长代写并注明 |
| 角色越界（改了别人的文件/范围） | diff 或报告发现 | 队长仲裁：可回退的回退，需保留的记录进黑板并在交付报告披露（审核岗的修复以修复记录为准，不算越界） |
