# 门禁裁决（gate）

> 第 4 步产出。**裁决只能由人做**——AI 整理证据、核对条件，不代填结论。
> 没有签署的本文件，不开写业务代码。轻量路径可简化为条件表**前三行**（含质检点）+ 三态勾选——质检点任何路径都不可省。
> 工件链：上游 ← behavior-contract / verdict+semantic-review / trace-matrix / redteam-report 证据｜下游 → 开发交接（接 delivery 时并入 `.agent-team/` 与 `.design_ok` 证据链）。

## 门禁条件核对

| 条件 | 状态 | 证据 |
| :-- | :-- | :-- |
| 业务真相：行为契约已被确认（或已声明代理并降级） | ☐ | behavior-contract.md 确认栏 / 「未经人工确认」声明 |
| 第 1 步：BLOCKER 清零（FABRICATED / MISSING-FILE / FORMAT-ERROR / READ-ERROR） | ☐ | verdict.md 汇总 + semantic-review.md |
| 第 1 步：质检点通过（抽 5 条 ✓ 无误判） | ☐ | 抽查记录（抽了哪 5 条、结果） |
| 第 2 步：核心链路断头路清零；非核心缺口显式登记 | ☐ | trace-matrix.md |
| 第 3 步：P0 风险每条有验证方式或修复方案 | ☐ | redteam-report.md P0 清单 |

## 裁决（三选一，人勾选）

- [ ] **Go**：上表全绿，且业务真相已人工确认
- [ ] **Go with Gaps**：非核心缺口按下表登记（负责人 + 期限）；**无专家路径的上限即本档**
- [ ] **No-Go**：理由 = 业务真相未定（连代理契约都没有）/ 无法在开发前澄清的事实性冲突 / 技术不可行。
      （No-Go 不是失败——它省下的是按错误文档开发的全部成本。）
