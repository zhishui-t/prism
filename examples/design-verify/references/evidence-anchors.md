# Evidence Anchors — 承重断言与锚点核查细则

> 第 1 步的操作手册。设计文档最致命的不是逻辑不优雅，而是引用了不存在的符号、接口、配置、文件——这一步在打磨格式和写测试**之前**做，否则白费功夫。

## 1. 什么算「承重断言」（锚什么，不锚什么）

**锚**（断言错了设计就塌，或照着做会出事故）：

- 引用具体存在的符号 / 文件 / 配置键 / 接口 / 主题 / 表结构（「OrderService 在下单后发送 inventory-deduct 消息」）
- 陈述现有系统行为（「当前结算走 v1 管道」「重试目前没有做」）
- 动数据、动钱、破坏兼容性、涉安全与权限的行为断言
- 数据流与边界条件（「库存扣减失败不阻断下单」）

**不锚**（锚了徒增噪音）：愿景与目标论述、风格与命名讨论、对全新要建之物的描述（它还没有可锚的代码）、常识性技术判断。

拿捏不准时问一句：**这条断言如果是编的，照着开发会不会做错？** 会 → 锚。

## 2. 账本格式（机器可查）

格式定义在 `templates/anchors.md`，要点：

- `## <id>` 起一条锚点（**id 单 token，如 A1 / A7**；小节说明用 `###` 或正文，`##` 严格保留给锚点）
- `claim:` 人读的断言（不参与核查）
- 文件锚点：`file:` + `quote:`（+ 可选 `line:`）——quote 必须是**单行内逐字子串**；省略 line 则全文搜索
- grep 锚点：`grep:`（**字面子串，非正则，不可为空**）+ `path:`（文件或目录，目录递归、跳过 .git 与 node_modules）+ `count:` 期望出现次数（**出现次数，非行数**）；`count: 0` = 断言「已不存在」（反向锚点）
- 路径相对 `--root`（缺省当前目录）解析；**`path:` 不要指向 `.design-verify/` 自身**——脚本已排除账本与 verdict.md 防自引用凑数，但把整个工作目录纳入扫描仍会引入噪音
- 锚点 id **必须唯一**且形如 `## A1`（`##` 后必须紧跟空格与单 token）；畸形二级标题与重复 id 都计 FORMAT-ERROR——无法定位的锚点不许静默跳过或覆写前一条

## 3. 机械核查（脚本）

```
node <skill目录>/scripts/check-anchors.mjs .design-verify/anchors.md > .design-verify/verdict.md
node <skill目录>/scripts/check-anchors.mjs .design-verify/anchors.md --only A1,A3   # 第 5 步定向复验
```

裁决与处置（**编造与漂移必须分开处置**）：

| 裁决 | 含义 | 级别 | 处置 |
| :-- | :-- | :-- | :-- |
| OK | 引文/计数核对通过 | — | 进语义层复核 |
| WRONG-LINE | 引文在文件里但不在锚定行（锚点漂移） | 动作项 | 把 line 刷新为实际行号，不堵门禁 |
| COUNT-MISMATCH | grep 计数与期望不符 | 动作项 | 刷新 count；found=0 时需人工确认是否已不存在 |
| FABRICATED | 引文在文件中找不到 | **BLOCKER** | 改断言（文档错）或改设计（设计错），修完定向复验 |
| MISSING-FILE | 文件/路径不存在 | **BLOCKER** | 同上 |
| FORMAT-ERROR | 锚点缺关键字段/格式坏/重复 id | **BLOCKER** | 修账本格式，无法核查的锚点不许静默跳过 |
| READ-ERROR | 目标读取失败（权限/坏软链） | **BLOCKER** | 修权限或路径后重跑，不许当作「查不到就算过」 |

退出码：0 = 无 BLOCKER；1 = 存在 BLOCKER；2 = 用法/账本错误（stdout 为空，原因在 stderr）。BLOCKER 汇总行非零 = 第 1 步门禁未过。

## 4. 语义层复核（独立实例，机械层查不出的错）

引文存在 ≠ 断言为真。机械层只证明「那行代码在那里」，不证明「断言说的就是那行代码干的事」。典型陷阱（复核实例逐条对照）：

- **使用 ≠ 实现**：「系统实现了 X 接口」——引文只是 import 或调用 X，不是实现 X
- **测试代码不算功能实现**：测试里的调用/桩不能佐证生产路径存在
- **注释与文档字符串不算行为**：注释说发消息 ≠ 代码发消息
- **断章取义**：引文所在分支可能是错误分支/死代码/feature flag 后面
- **时态错位**：断言说「目前」，引文是刚加的新代码或待删的旧代码

派单要求：**独立实例**（reviewer 角色或挂 spec-vs-impl-checker 技能的实例），绝不复用写设计文档的会话；逐条输出「断言 ↔ 引文语境是否一致」的判断与理由，落 `semantic-review.md`；语义层判 FABRICATED 同样计 BLOCKER。

## 5. 质检点（人，整条链唯一的直接人验）

- 每批机械层结果**随机抽 5 条 OK**，由人打开文件亲自核对（行号对得上、引文在那一行、断言没曲解）
- 抽查发现 1 条误判 → **该批作废重跑**，并检查：`--root` 是否指对、文件编码、锚点格式（quote 里有没有不可见字符）
- 目的：确定性脚本也会有 bug 与误报，独立实例也可能敷衍——没人抽查复核器，后面所有 ✓ 的成色都只是工具自述
- 抽查记录（抽了哪 5 条、结果）写进 gate.md 的证据列
