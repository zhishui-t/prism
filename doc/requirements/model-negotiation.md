# Prism 模型与子 Agent 管理：边界声明

> 状态：**边界声明，非设计文档**
> 日期：2026-09-09
> 结论：**Prism 不参与子 agent 管理与模型选择。**

---

## 1. 为什么不做

每个 harness（ZCode / Codex / Claude Code / Cursor …）**自己的子 agent 管理方式各不相同**，且多数不对外暴露完整语义。Prism 无法知道：

- 宿主如何创建、复用、回收子 agent；
- 宿主如何选择模型、能否指定、不支持时怎么降级；
- 宿主在派发链路中哪里可以设卡。

**在不知道的前提下设计协议，就是瞎猜。** 猜出来的接口必然与真实宿主不符，还会让 Prism 背上它不该背的耦合。

---

## 2. 边界

| 属于宿主 | 属于 Prism |
| :--- | :--- |
| 子 agent 创建/复用/回收 | 不参与 |
| 模型选择与降级 | 不参与 |
| 派发路径与并发控制 | 不参与 |
| 成本与配额策略 | 不参与 |
| — | 在角色定义里**声明**推荐能力（纯信息） |
| — | 记录任务台账（被动，见任务中心） |

**Prism 不探测宿主的模型清单，不设模型准入，不做降级协商。** 这些都是宿主私事。

---

## 3. 角色定义里的声明字段（可选，纯信息）

角色定义可带一个**仅供人读**的推荐字段，Prism 不校验、不执行：

```yaml
# 角色定义（AGENTS.md frontmatter）
recommend:
  capabilities: [reasoning]        # 该角色适合什么能力档次的模型
  note: 安全审计建议使用强推理模型
```

**语义**：像岗位说明书里写"本岗需本科以上"——写下来供参考，**不构成拦截条件**。

**Prism 的行为**：
- 校验字段格式合法；
- 在控制台展示；
- **不据此拒绝任何请求、不参与任何协商。**

---

## 4. 之前的错误设计（已废弃）

| 废弃项 | 原因 |
| :--- | :--- |
| 主动准入（派发前必须声明 plan） | 假设 Prism 在派发路径上，不成立 |
| 三态协商（admitted/downgraded/inherited） | 依赖宿主回报，宿主未必支持 |
| 团队模型池 + 上限校验 | 需要 Prism 知道可用模型，只能靠猜 |
| 探测宿主模型目录 | 方向错误（伸手进宿主）+ 依赖宿主私有 API |
| 能力标签表 + 一致性校验 | 建立在"Prism 参与选择"的假设上 |

以上全部撤回。

---

## 5. 唯一保留的事实

以下事实对实现有用，但不改变边界：

- **代码图谱的 token 成本**：代码零 token（AST），文档走 LLM（见知识库文档）。
- **模型清单若要知道**：只能由宿主主动告知，Prism 不主动探测；且**即使知道也不用于决策**。
