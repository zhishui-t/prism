# Prism v0.1.0-alpha

**首个按平台自包含的 alpha 发行版。** 解压即用：**不需要 git、不需要联网**，也不会再去 GitHub 下载运行时。

> `-alpha` = 接口与产物形态仍在动，用于**试用与反馈**，不建议生产依赖。

sha256sum -c SHA256SUMS        # 或 Windows: certutil -hashfile <tgz> SHA256

## 为什么分包

包内自带本平台的**三方运行时与最小向量模型**，而它们**不可跨平台复用**：

- `llama-server` 二进制（CPU 自编译 + **Vulkan** GPU 预编译）——按平台/算力编译或下载；
- `anydoc` 原生绑定（napi `.node`）——Rust 原生库，平台专属；
- 这两者决定了「一个包只能服务一个平台」，所以 mac 版必须另出。

## 快速开始

```bash
tar -xzf prism-0.1.0-alpha_win_x64.tgz
cd prism-0.1.0-alpha_win_x64

node bin/prism.js --version     # prism 0.1.0-alpha
node bin/prism.js doctor        # 一次自检三方件与向量运行时
node bin/prism.js serve         # 控制台 http://127.0.0.1:7777
```

要求 **Node ≥ 22.5**。`doctor` 在干净解压环境下应全 `ok`（除「端口占用」这类环境项）：

```
ok  graphify  — python -m graphify 版本: 0.9.57（vendored）
ok  anydoc    — 文档转换可用（docx/pdf/xlsx/pptx/csv → Markdown）
ok  embedding — 就绪（档位 small／BGE-small-zh-v1.5，512 维，GPU/Vulkan，127.0.0.1:8191）
```

## 两个已知边界（不是缺陷，是取舍）

1. **代码图谱需要本机 Python ≥3.10 与依赖**：`tree-sitter` 系列 + `networkx` / `numpy` /
   `rapidfuzz`。Python 环境无法可靠内嵌，故未随包——目标机跑
   `pnpm run 3rd:build`（即 `python -m pip install ...`，**这一步需要联网或内网源**）。
   未装时**只有代码图谱降级**，知识库检索、文档转换、架构图渲染照常可用。
2. **只随包最小向量模型**：`bge-small-zh-v1.5`（512 维，CPU）。要大档位（`bge-m3` /
   `Qwen3-Embedding`，各 600MB+）跑 `prism embedding install --tier default|large`。

## 体积取舍

为控制下载体积，打包**排除**（有依据，见 `3rd/README.md`）：

- `3rd/llama.cpp` 源码 173MB —— 只有 `setup-embedding.mjs --source` 的源码编译路径需要，运行时已随包；
- `3rd/llama-runtime/build` 95MB —— 本地编译中间产物；
- 3rd 子模块里与运行无关的 docs / examples / tests 约 46MB —— 全仓 grep 零引用。

## 本版其他改动

- **版本不再硬编码**：MCP `initialize` 的 `serverInfo.version` 与 HTTP `/api/health` 的
  `version` 均改为读本包 `package.json`（此前写死 `0.1.0`，发版即脱节）；
- 打包产物改为**按平台命名**，并同时产出 `SHA256SUMS` 与包内 `PRISM-MANIFEST.json`；
- 打包期**前置校验运行时**：缺任何一项（llama 主二进制 / Vulkan / anydoc 原生 / 最小模型）
  直接让打包失败，绝不出「解压了却跑不起来」的包；
- 发行冒烟 `pnpm run test:package` 扩到 **21 项**，重点转为「**不跑任何安装脚本**也直接可用」。

## 破坏性 / 签名变更

- **`deleteExternalSkillDefinition` 的 `skillsDir` 参数由 `string` 放宽为 `unknown`**（`@prism/server`）：
  函数入口自行做「trim 后非空」校验——缺参或空白值一律返回域错误 `bad_request`
  （`skills_dir_required`），**不再以裸 `TypeError` 冒泡**。这是「技能删除三面（HTTP / MCP / CLI）
  对称」的连带变更：MCP 面 `prism_skill_rm` 把 `skills_dir` 列入 `required`，服务端据此与
  `deleteRoleDefinition` / `deleteTeamDefinition` 统一错误形态，且**绝不回落默认宿主目录**。
  调用方若原先依赖「不传即抛 `TypeError`」来兜底，请改为读取返回的 `code`。
